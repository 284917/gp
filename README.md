# Голос компании

Платформа программы амбассадоров бренда работодателя: кабинет амбассадора для сотрудников и студентов и кабинет куратора для управления программой.

Проект команды для кейса **Intelligence CUP** («HR и бренд работодателя — программа амбассадоров»).

## Что умеет

**Публичная часть**
- Главная страница программы: кто такие амбассадоры, путь из четырёх уровней, сезон сентябрь — май, награды, вопросы.
- Заявка в программу: роль (офис, АЗС и нефтебаза, вуз, колледж), регион, место работы или учёбы, мотивация, согласие на обработку данных.

**Биржа инициатив** (`/me/initiatives`, `/me/formats`, `/curator/initiatives`)
- Любой амбассадор предлагает проект: формат, регион, аудитория, кого ищет, ожидаемый результат. Есть готовые совместные механики: «Голос профессии», «Один вопрос, три взгляда», «Региональный вызов».
- Путь проекта: идея → набор команды → в работе → завершена. Куратор согласует идею и принимает итоги, команду собирает и ведёт автор.
- Завершённый проект с итогами и инструкцией попадает в библиотеку форматов. Кнопка «Повторить в моём регионе» создаёт новую инициативу со ссылкой на исходную.
- Баллы за вклад: автору, каждому в команде, бонус смешанной команде из сотрудников и студентов и автору формата, когда его повторили в другом регионе.
- Метрики самостоятельности в кабинете куратора: индекс инициативности, доля смешанных команд, доля повторённых форматов, удержание участников, схема тиражирования между регионами.
- Уровни учитывают вклад в инициативы: «Эксперт» — 600 баллов и участие в завершённой инициативе, «Лидер» — 1200 баллов и своя реализованная инициатива.
- Карьерная мотивация без привилегий: преимущества при отборе на практику нет, вместо него — карьерные консультации с HR, встречи с экспертами и подготовка к отбору. Бонусы программы лояльности убраны из каталога.

**Кабинет амбассадора** (`/me`)
- Путь: уровень и баллы, цель недели, тандем «сотрудник + студент», сезон, уведомления.
- Задания недели под свою роль, сдача текстом, ссылкой или файлом (фото, видео, голосовое), история проверки.
- Контент-кит: личная ссылка на страницу карьеры с UTM-меткой (канал и номер амбассадора), конструктор поста, ключевые сообщения, сценарии роликов, памятка «можно / нельзя», каналы.
- Рейтинг региона и кубок регионов (по среднему баллу).
- Награды: обмен баллов на опыт, обучение, карьерные возможности и мерч.
- Профиль, история заданий, бонусные баллы, смена пароля.
- «Вопрос куратору» (`/help`): форма для всех, в том числе без входа — если забыт пароль. Ответ приходит уведомлением в кабинет.
- Для капитанов регионов — проверка заданий своего региона.

**Кабинет куратора** (`/curator`)
- Обзор: что требует внимания, ключевые показатели, контент по неделям, нагрузка кураторов и капитанов, активность по сегментам, воронка «от публикации до найма», метрики программы с целями сезона.
- Модерация заданий, заявки в программу, выдача наград.
- Амбассадоры: поиск и фильтры, карточка с историей, назначение капитана, пауза, наставник-тандем, бонусные баллы, напоминания, сброс пароля (временный пароль, при входе участник задаёт свой).
- Вопросы участников: ответ уходит уведомлением в кабинет, вопрос «не могу войти» закрывается сам после сброса пароля.
- Задания: публикация и редактирование, аудитория, способ сдачи, кто проверяет.
- Регионы: схема с часовыми поясами, капитаны, активность.
- Метрики: ежемесячный ввод охвата, откликов, наймов и заявок на практику.

## Технологии

- Next.js 15 (App Router, серверные компоненты и server actions), React 19, TypeScript.
- PostgreSQL через библиотеку `postgres`. Схема — в `migrations/`, применяется автоматически при сборке.
- Вход по почте и паролю (bcrypt), сессия в подписанном cookie (JWT).
- Загрузка файлов — Vercel Blob (необязательно).
- Шрифты Golos Text и Roboto Condensed подключены локально, без внешних запросов.

## Запуск на Vercel

1. **Импорт проекта.** На vercel.com: *Add New → Project*, выберите репозиторий `284917/gp`. Настройки сборки менять не нужно.
2. **База данных.** В проекте откройте *Storage → Create Database → Neon (Postgres)* и подключите её к проекту. Переменные `DATABASE_URL` и другие появятся автоматически.
3. **Переменные окружения** (*Settings → Environment Variables*):
   - `AUTH_SECRET` — длинная случайная строка (например, результат `openssl rand -hex 32`).
   - `ADMIN_EMAIL` и `ADMIN_PASSWORD` — почта и пароль главного куратора (пароль от 8 символов). При каждой сборке этот аккаунт создаётся или получает роль куратора и пароль из переменной — так доступ всегда можно восстановить через Vercel.
4. **Файлы (по желанию).** *Storage → Create → Blob* (доступ *Private*), подключите к проекту — Vercel добавит `BLOB_STORE_ID`, и амбассадоры смогут прикреплять фото, голосовые и короткие видео до 4 МБ (фото сжимаются в браузере). Файл видят только автор, капитан его региона и кураторы. Для публичного хранилища задайте `BLOB_ACCESS=public`, вне Vercel — `BLOB_READ_WRITE_TOKEN`.
5. **Пересоберите проект:** *Deployments → … → Redeploy*. При сборке создаются таблицы, регионы, стартовые задания, каталог наград и аккаунт главного куратора.
6. **Проверка:** откройте `/api/health` — должно быть `"ok": true` и `"database": "connected"`.

### Первый запуск программы

1. Войдите на `/login` почтой и паролем из `ADMIN_EMAIL` и `ADMIN_PASSWORD` — откроется кабинет куратора.
2. Отправьте ссылку на заявку (`/join`) сотрудникам и студентам. Заявки появятся в разделе «Заявки».
3. Примите участников, назначьте капитанов регионов и наставников для студентов в карточках амбассадоров.
4. Публикуйте задания недели в разделе «Задания». Стартовый набор заданий и каталог наград уже есть — их можно править.
5. Раз в месяц вносите охват, отклики и наймы в разделе «Метрики».

Других кураторов пока заводят через базу данных; главный куратор задаётся переменными окружения.

## Локальная разработка

```bash
npm install
cp .env.example .env.local   # укажите DATABASE_URL своей базы Postgres
npm run db:migrate           # таблицы и начальные данные
npm run dev                  # http://localhost:3000
```

## Проверка качества

Каждый push запускает GitHub Actions (`.github/workflows/ci.yml`): установка, миграции на чистой базе Postgres, сборка, повторный запуск миграций и автотест в браузере. Автотест сам заводит участников через заявки и проходит весь путь: одобрение куратором → назначение капитана и наставника → сдача задания → проверка капитаном → баллы → обмен на награду → выдача, а также мобильная версия и тёмная тема. Скриншоты всех экранов сохраняются в артефакте `screenshots`.

## Структура

```
migrations/          SQL-схема базы
scripts/migrate.mjs  миграции и начальные данные (запускается при сборке)
scripts/seed.mjs     справочники: регионы, стартовые задания, награды; главный куратор
scripts/smoke.mjs    автотест сценариев в браузере
src/app/             страницы: главная, вход, заявка, /me, /curator
src/app/actions/     серверные действия: вход, задания, проверка, управление
src/components/      интерфейс: карточки, формы, графики, навигация
src/lib/             база, сессии, справочники программы, статистика
```
